Bugs / Product behavior
B-01
HighData integrity

Gist sync can overwrite data after a failed read

HTTP errors, missing content, and invalid JSON all become null. The sync path treats that as an empty Gist and may replace the remote library with the local collection.

src/lib/gist.ts:59–79 · src/store/useStore.ts:142–146
Fix and acceptance criteria
  • Return distinct results for empty, missing, invalid, and failed reads.
  • Only initialize after a successful response confirms an empty library.
  • Require confirmation before replacing malformed content.
  • Add tests for 403, 404, 5xx, invalid JSON, empty data, and valid data.
B-02
HighState

Rating updates duplicate history entries

toggleWatched(media, rating) never stores the rating. A truthy rating on an existing item appends another copy instead of updating it.

src/store/useStore.ts:217–229
Resolution
  • Existing history entries are updated by media key and retain their metadata and favorite state.
  • Any duplicate entries for the same media key are removed during a rating update.
  • New history entries store a supplied rating without changing normal toggle behavior.
  • The unsupported star/TMDB synchronization claim was removed from the README.
  • Lint and production build completed successfully.
B-03
MediumData fetching

Movie and TV detail caches can collide

Providers, cast, images, ratings, and external IDs are cached by numeric ID only. A movie and show sharing the same TMDB ID can display each other’s metadata.

src/components/DetailsSheet.tsx:105–109, 259–288
Fix and acceptance criteria
  • Key all detail state with getMediaKey() or {id, media_type}.
  • Verify switching directly between a movie and show with the same numeric ID.
  • Ensure loading and error state is also scoped to the full media key.
B-04
MediumPWA

Offline mode blocks the local collection

The offline guard replaces the entire app, while the service worker caches only visited navigation documents. This conflicts with the advertised offline support.

src/components/OfflineGuard.tsx:24–50 · public/sw.js:38–64 · README.md:45
Fix and acceptance criteria
  • Keep IndexedDB library browsing available without a connection.
  • Disable or label only network-dependent actions.
  • Precache the application shell and required static assets.
  • Test a cold offline launch and an offline launch after first visit.
B-05
MediumRequirement

TV migration uses 30 days instead of 7

The migration window now matches the documented behavior: watched shows return to the playlist when the next episode airs between today and seven days from today.

README.md:32 · src/store/useStore.ts:11–13, 292–297
Resolution details
  • Uses the named constant TV_MIGRATION_WINDOW_DAYS set to 7.
  • Includes episodes airing today and up to seven days ahead.
  • Ended and canceled shows remain excluded.
B-06
MediumBackup

Sync and backups omit tracking state

The schema preserves playlist, history, and favorites, but drops ratings and played episodes during a restore.

src/lib/gist.ts:52–57 · src/store/useStore.ts:122–130
Fix and acceptance criteria
  • Create a versioned schema containing all collection-related state.
  • Add migrations for existing version 1 and 2 files.
  • Round-trip test ratings, favorites, played episodes, dates, and media sources.
B-07
LowInteraction

Escape can close the lightbox and details sheet

The lightbox and global shortcut handlers both receive Escape, so the topmost modal and its parent sheet may close together.

src/components/DetailsSheet.tsx:210–222 · src/components/KeyboardShortcuts.tsx:14–17
Resolution
  • Image, trailer, and confirmation overlays capture Escape before the global sheet shortcut.
  • First Escape closes only the topmost overlay; a subsequent Escape closes details.
  • Nested focus traps keep keyboard focus inside the active overlay.
  • Modal roles and accessible labels identify each overlay.
B-08
LowInteraction

Keyboard shortcuts bypass removal confirmation

W and E directly toggle list membership, while the visible controls ask for confirmation before removing an existing item.

src/components/KeyboardShortcuts.tsx:27–36
Resolution
  • W and E route through the rendered Playlist and History controls.
  • Removal therefore uses the existing confirmation flow instead of mutating state directly.
  • Disabled controls and active modal overlays block the shortcuts.
  • Inputs, textareas, and editable content continue to ignore these shortcuts.
  • Shortcut routing is covered by automated tests.
Security / Operations
S-01
HighDependency

Upgrade vulnerable dependencies

Next.js and Capacitor were upgraded, the Capacitor CLI was moved to development dependencies, and safe audit updates were applied. The app still builds successfully.

package.json · package-lock.json
Resolution and accepted risk
  • Next.js and eslint-config-next upgraded to 16.2.12; Capacitor packages upgraded to 8.4.2.
  • The critical tar advisory and the xmldom finding were removed by updating tooling and classifying the CLI as development-only.
  • The remaining production-classified findings are Next.js, its build-time PostCSS copy, and Sharp. The project deploys only the static out/ directory to GitHub Pages—not the Next.js server or node_modules.
  • Remaining full-audit findings are in lint/build tooling and process only trusted repository input. Do not use npm audit fix --force; it proposes incompatible Next.js 9 and ESLint 10 downgrades/upgrades.
  • Reopen this issue if the app moves to a Next.js server deployment, build inputs become untrusted, or patched upstream releases become available.
S-02
HighAbuse prevention

Protect the public game API Worker

CORS does not authenticate callers. Requests without an Origin can use the Worker and consume IGDB, HLTB, and Cloudflare resources.

worker/src/index.ts:100–106, 603–646
Completion criteria
  • Add rate limiting and request-size/query limits.
  • Reject disallowed browser origins before upstream work.
  • Add monitoring for request volume, errors, and upstream quota use.
  • Evaluate signed requests or another app-specific authorization mechanism.
S-03
RecommendationCredentials

Reduce exposure of Gist credentials

The GitHub token is persisted in browser IndexedDB. An XSS payload or malicious extension could retrieve it.

src/store/useStore.ts:78–79, 95–97, 347–349
Completion criteria
  • Recommend a narrowly scoped fine-grained token in the UI.
  • Clearly disclose that the token is stored locally.
  • Consider an opt-in session-only storage mode.
  • Authenticate Gist reads to avoid anonymous API rate limits.
